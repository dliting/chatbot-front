## 1. 产品概述

### 1.1 产品定位
**本项目是一个通用的AI聊天前端组件AIChat，基于Vue框架，支持离线部署和运行。**

基于 Vue 3 + TypeScript 开发的可嵌入 AI 聊天机器人前端组件，支持扩展模式、边栏模式、悬浮模式三种交互形式，具备响应式布局、多模态交互能力。

### 1.2 目标用户
- 需要在网站中集成 AI 对话功能的开发者
- 需要可定制化 Chatbot UI 的产品团队
- Vue 3 项目开发者（组件化嵌入）
- 非 Vue 项目开发者（iframe 嵌入）

### 1.3 核心价值
1. **开箱即用**: 无需复杂配置即可集成到现有项目
2. **离线部署**: 支持完全离线部署和运行
3. **响应式设计**: 自适配 PC/移动端不同屏幕尺寸
4. **多模态交互**: 支持文本、图片等多种输入方式
5. **灵活嵌入**: 支持 Vue 组件和 iframe 两种嵌入方式

### 1.4 项目结构

```
.
├── README.md           # 项目总体说明
├── public              # 静态资源
├── docs                # 文档

│   └── chatapp         # 示例项目（ChatApp演示应用）
├── tests               # 测试用例和代码

```

## 2. 交互形式定义

> **架构说明**: 本组件采用双维度架构设计，将"交互模式"与"布局形式"解耦。

### 2.1 布局形式（Layout）

| 布局 | 说明 |
|------|------|
| **平铺模式（Extended Layout）** | 会话列表和聊天窗口在同一页面展示 |
| **紧凑模式（Compact Layout）** | 会话列表和聊天窗口在不同页面展示 |

### 2.2 交互模式（Interaction Mode）

| 模式 | 说明 |
|------|------|
| **扩展模式（Extended）** | 作为全屏页面，内部使用平铺模式布局 |
| **边栏模式（Sidebar）** | 作为边栏，内部使用紧凑模式布局 |
| **悬浮模式（Floating）** | 悬浮球 + 悬浮窗口，内部使用紧凑模式布局 |

### 2.3 组合关系

| 交互模式 | 内部布局 | 说明 |
|---------|---------|------|
| extended | split | 平铺布局，会话列表始终显示在左侧 |
| sidebar | compact | 紧凑布局，通过Tab切换"会话"/"聊天"视图 |
| floating | compact | 紧凑布局，通过Tab切换"会话"/"聊天"视图 |

## 9. 测试要求

### 9.1 单元测试
- 单元测试覆盖率应大于 80%
- 遵循 TDD 开发原则
- 使用 Vitest 作为测试框架

### 9.2 UI交互测试
- 使用 `chrome-devtools-mcp` 插件进行前端UI交互测试
- 详细测试指南请参考 `tests/UI_TEST_GUIDE.md`
- 测试应覆盖所有交互模式和共用功能

### 9.3 整体回归测试
AIChat组件整体回归测试，应分别就下述两种后端模式进行测试：
1. **Mock模式**: 运行后端mock模式服务器进行测试，后台访问虚构响应
2. **Real模式**: 运行后端real模式服务器进行测试，后台访问本地Ollama大模型服务

> 如果本地Ollama服务无法访问，则直接认为此测试失败

### 9.4 测试原则
- 测试应从ChatApp首页入手，逐级检查各模块功能
- 交互测试中的每个操作响应一般不超过3分钟，否则认为响应超时
- 测试产生的脚本和临时数据，要放在测试目录下
- 测试通过后应及时清理测试脚本和临时数据

## 10. 开发规范

### 10.1 基本原则
- **代码风格**: 代码风格要统一，遵循项目ESLint配置
- **代码简洁**: 代码要简洁，尽量避免冗余
- **可维护性**: 代码要易于维护和扩展，遵循良好的软件设计原则
- **配置分离**: 和部署环境相关的配置信息，要放在单独的配置文件中

### 10.2 修改Bug
- 修改Bug时，要考虑问题的根本原因
- 避免同类问题在代码迭代过程中反复出现

### 10.3 新增或变更功能
- 新增或变更功能时，要考虑功能的适用性，避免添加无用功能
- 新增或变更功能时，不应影响原有其他功能
- 新增或变更功能时，应同时更新 `docs` 目录下的相关文档

### 10.4 文件和目录管理
- 项目要可以离线部署，第三方字体、图片和组件等，应当下载到本地合适目录后再引用
- 新建目录或文件时，要注意项目其他位置是否已经有同样功能的目录和文件，避免重复

### 10.5 代码提交
- 所有测试通过后，才能提交代码
- 代码提交前，要确保所有代码都经过 ESLint 检查，并且没有语法错误
